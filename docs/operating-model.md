# Operating model

The board is intended to fit into normal work rather than create a separate reporting exercise.

## Preferred update paths

1. Say the update during the approved meeting. The transcript and meeting summary provide the source evidence.
2. Post a relevant update in the designated team chat. A helpful convention is `board update STB-###`, followed by plain language.
3. Point a desktop agent at the shared working folder and describe the update privately. The agent should read the instructions and workbook before making a change.

Direct Excel editing is supported as a fallback, but is not the preferred experience. The user should normally copy an existing task row to the Updates tab, preserve the columns, and edit only the proposed update. Do not delete processed rows or manually maintain the board’s complete current state.

## Agent guardrails

- Read the instructions and relevant task context first.
- Work only on open update rows unless an administrator explicitly directs otherwise.
- Leave new Update ID cells blank. Central processing assigns row-based IDs.
- Do not rewrite the whole workbook.
- Do not alter unrelated tasks, formulas, sheets, or formatting.
- Do not infer removal from a missing row. Removal requires an explicit instruction, stable Card ID, and reason.
- If the update is ambiguous, leave it for review rather than guessing.

## Human expectations

A useful update usually explains what changed, the current status, the owner, priority, and a logical target date. Not every field is required for every lightweight update. The goal is clarity and forward movement, not form completion.
